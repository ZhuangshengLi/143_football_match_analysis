# Football Match Analysis

A football match data analysis project based on the European Soccer Database. Transforms raw match and player data into structured datasets for machine learning and visualization.

---

## Project Structure

All source code is organized as modular `.py` files for maintainability and reuse:

```
143_football_match_analysis/
├── main.py                    # CLI entry: process | train
├── requirements.txt          # Third-party dependencies
├── workflow.ipynb             # Jupyter notebook: all visualizations for presentation
├── inputs/
│   ├── __init__.py
│   ├── match_features.py      # L1/L2/L3 feature engineering
│   └── raw/
│       └── database.sqlite    # Raw DB (download from Kaggle)
├── outputs/
│   └── clean/
│       └── processed_dataset.npz   # Generated by main.py process
├── models/
│   ├── __init__.py
│   └── ablation.py            # Model A/B/C/D ablation
└── visualization/
    ├── visualization.py       # Plot functions (data overview, match/league, feature impact, non-linear)
    ├── ECE143_Data_Visualization.ipynb
    ├── ECE143_Non-Linear_Visualization.ipynb
    └── ...
```

**Source code locations:**
- `main.py` — Entry point and CLI
- `inputs/match_features.py` — Feature engineering (build_match_dataset, load_match_dataset, get_feature_groups)
- `models/ablation.py` — Ablation experiments (run_ablation)
- `visualization/visualization.py` — All plot functions used by workflow.ipynb

## Jupyter Notebook (Visualizations)

**`workflow.ipynb`** — Single notebook that demonstrates all visualizations for the presentation:
- Section 1: Environment & paths
- Section 2: Data preprocessing (L1/L2/L3 features)
- Section 3: Model training (A/B/C/D ablation, metrics charts)
- Section 4: Visualization — data overview, match/league stats, feature impact, player/team analysis, non-linear (SVD, t-SNE, Kernel PCA)

Open `workflow.ipynb` in Jupyter and run cells top to bottom. Ensure `database.sqlite` is in `inputs/raw/` and run Section 2 before Section 3 and 4.

## How to Run

### 1. Install dependencies

```bash
pip install -r requirements.txt
```

### 2. Feature engineering (build L1/L2/L3 dataset)

```bash
python main.py process
# Or with custom paths:
python main.py process -d inputs/raw/database.sqlite -o outputs/clean/processed_dataset.npz --min-date 2010-02-22
```

### 3. Train models (A/B/C/D ablation)

```bash
python main.py train
# Or:
python main.py train --data outputs/clean/processed_dataset.npz
```

### 4. Run visualizations

Open `workflow.ipynb` in Jupyter and execute all cells.

## Technical Documentation

### 1. Data Processing Pipeline

```
database.sqlite
    │
    └─► build_match_dataset()     # Match feature engineering
            • L1: Player_Attributes aggregation (overall, attack, defense, passing, pace, physical, gk)
            • L2: Team_Attributes tactical style (buildUpPlay, chanceCreation, defence)
            • L3: Match rolling history (win rate, goal diff, Elo, rest days)
            • Strict time alignment: date ≤ match_date
            • Output: processed_dataset.npz
```

### 2. Feature Framework

| Level | Content | Source |
|-------|---------|--------|
| **L1 Static Ability** | overall_mean, attack/defense/passing/pace/physical/gk_index, diff, attack vs defense matching | Player_Attributes |
| **L2 Tactical Style** | buildUpPlaySpeed, chanceCreation*, defencePressure, etc. | Team_Attributes |
| **L3 Dynamic State** | Last 5 win rate, goal diff, home win rate, rest days, Elo | Match rolling history |

**Time alignment**: Player/team attributes use the most recent record with `date ≤ match_date`; L3 rolling/Elo uses only historical matches with `date < match_date` to avoid data leakage.

**Ablation experiments**: Model A (L1) → B (L1+L2) → C (L1+L2+L3) → D (C+odds)

### 3. Output Data Format

| Key | Description |
|-----|-------------|
| X | (N, n_features) Feature matrix |
| y | (N,) Labels. 0=home did not win, 1=home win |
| feature_names | Feature column names |
